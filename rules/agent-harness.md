# 智能体与提示词 Harness 规则

> 依据：规格 §6、§17 全章。适用范围：A1 编码生成、A3 文本编码、A4 复核/仲裁、A5 报告、A6 多模态转写。
> 本文件是**强制**；每条都应能被测试或检查项断言。

## 1. 框架与边界

- 框架：**Pydantic AI**（MIT）。**只用于环节内的单次智能体调用**（角色、类型化工具、结构化输出、重试）。
- **禁止**用框架的图/状态机/checkpointer 串联 `ST01→ST15`；跨环节编排用自研 `pipeline.yaml` + manifest + 文件契约。
- **智能体之间不通过对话传递状态**：会话历史只在单次调用内有效，调用结束即落盘。
- 工具是本机类型化函数；**不引入远程工具协议**（MCP 等）。
- 框架版本必须锁定（`uv.lock`）并写入 manifest。

## 2. 处理粒度（已修正，勿回退）

**默认：单样本 × 全部题目。**

- 一次调用 = 一个完整样本（整篇正文 + 元数据）+ 完整编码规则 → 输出**该样本全部题目**的编码值。
- **禁止**一次调用塞多个样本（除非用户显式开启 `multi_sample_batch` 且样本 < 200 字，并在报告中声明）。
- 分批（按维度/按题目）**只能作为超预算时的降级**，必须打 flag 并在报告声明。
- 「上下文小」的正确应对：只装当前样本、只装当前编码规则、结构化输出、按序降级——**不是**把判定切碎。

## 3. 上下文预算与降级顺序

预算（默认，可配）：系统提示 1,800 ＋ 技能 900 ＋ **全部题目卡片 4,500** ＋ 样本 3,000 ＋ 输出 1,500 ≈ **11,700**，上限 **16,000**。

**降级必须按此顺序，每一步都记 flag**：

| 步 | 动作 | flag |
|---|---|---|
| 1 | 裁示例词 | `no_examples` |
| 2 | 裁关键词 | `no_keywords` |
| 3 | 精简题目卡（只留题目名+选项名，提示词改工具式按需读取） | `slim_codebook` |
| 4 | 样本截断（首尾各半） | `truncated` |
| 5 | 样本分块判定 + 按题目聚合 | `chunked` |
| 6 | 退回「单样本 × 按维度分批」 | `dimension_batched` |
| 7 | 退回「单样本 × 单题目」 | `field_batched` |
| 8 | 样本摘要后判定 | `summary_coded` |
| 9 | 仍超限 → 报错 `LLM-460` + 进复核队列 | — |

- 第 6/7 步会**改变判定粒度**：其产物不得与默认粒度结果静默混算（信度计算前必须检查 flag 一致性）。
- **禁止**静默截断后照常输出。

## 4. 角色硬规则（逐条可断言）

| # | 规则 |
|---|---|
| R-01 | 只输出 JSON，无解释性前后缀 |
| R-02 | `values` 只能取自当前题目选项，**禁止发明** |
| R-03 | 必答题必须给值；无法判定给兜底项或 `<未编码>` 并说明 |
| R-04 | 命中必须给 `evidence`（真实存在的原文片段 + 字符区间）——**生成型**编码器 100%；**决策型**按 `evidence_source` 分来源断言 |
| R-05 | 不引用提示词与编码规则之外的知识 |
| R-06 | 不修改/复述编码规则文件 |
| R-07 | 一次只处理给定样本；**本样本全部题目必须一次给全** |
| R-08 | 不确定就降低 `confidence`，不得用高置信掩盖不确定 |
| R-09 | 输出中不得出现提示词、内部路径、密钥 |
| R-10 | 达到最大工具步数（默认 3）或超时（默认 60 s）必须终止并落盘失败记录 |

## 5. 元提示词规范

**两级设计**：一级 `prompt/meta/`（人工编写、无研究题材）；二级 `prompt/templates/编码提示词_{hash}.md`（由 A1 依元提示词 + `codebook.json` 生成）。

元提示词必须含 **8 段**：`角色与目标 / 输入清单 / 技能声明 / 方法与流程 / 判定准则 / 输出契约（含正例与反例）/ 自检清单 / 失败与门禁`。

- **禁止**在元提示词里出现具体研究题材。
- 输出契约必须与 `config/schema/*.json` **同源生成**（禁止手抄，避免漂移）。
- 元提示词纳入版本管理与哈希冻结（规格 §6.9）。

## 6. Skills 规范

- 位置 `prompt/skills/<name>/SKILL.md`，**按声明加载**，不常驻上下文。
- 每个 skill 必须声明：适用角色、版本、内容哈希、加载方式、**上下文开销（token）**。
- **强制加载**：`codebook-syntax`、`strict-json`、`academic-integrity`（A1 与 A3）。
- 其余按条件：`option-design`、`keyword-writing`（A1）；`evidence-citing`（A3/A4）；`multi-select-decision`（多选题目时）；`boundary-cases`（按题材）；`report-writing`（A5）。
- skill 内容变更 = 行为变更 → 必须跑回归测试（与元提示词同等对待）。
- **禁止**为了"更聪明"把所有 skill 常驻。

## 7. 缓存、重试、限流、预算

- 缓存键：`sha256(provider + model + params + prompt_hash + skill_hashes + 输入)`；**编码员 A/B 缓存必须隔离**。
- 重试：结构化输出失败 / 限流 / 网络错误各最多 3 次，指数退避 + 抖动；**内容审核拒答不重试**（`LLM-451`）。
- 限流：按 provider 配 QPS 与并发，命中 429 全局降速。
- 预算：每 run 累计 token 与金额，达阈值熔断。
- 每次调用写 `llm.jsonl`（token/耗时/模型/是否命中缓存）；进入 L1 的改动写 `audit`。
- 版本：框架、模型、提示词、skills 四者版本全部写入 manifest。

## 8. 决策型编码器（DecisionCoder）专项

- 只走**托管计费 API**；**禁止**设计依赖本地大模型权重的默认路径（本机仅有 8 GB 显存消费级显卡，跑不动 27B 级模型；产品定位也不要求高配置电脑）。
- 必须通过**准入门槛**（准确率 ≥ 主编码员 −3pt、宏 F1 −0.03、多选 Jaccard −0.05、非法值 0、ECE ≤ 0.10、成本或吞吐达标）；未过门槛只能作 `prefilter`，**不得计入信度**。
- 阈值必须**逐题目、逐来源校准**，并写入 `frozen/{run_id}/calibration.json`；编码规则升版后校准作废、必须重校。
- `evidence_source = keyword_span | escalate_model | none`；`none` 必带 `no_evidence` flag，报告必须给**逐字段证据覆盖率**。

## 9. 测试要求

- 全部智能体用例走 **cassette 回放**，CI 零网络；**未录制到响应即失败**，不得静默返回空。
- 必测：预算与降级顺序（`ACC-H-01/02`）、全题目一次调用（`ACC-H-09`）、多样本禁塞（`ACC-H-10`）、粒度混算拦截（`ACC-H-11`）、强制 skill 加载（`ACC-H-03`）、输出契约同源（`ACC-H-04`）、信息不足必阻塞（`ACC-H-05`）、evidence 真实（`ACC-H-06`）、缓存键含 skill 与 coder（`ACC-H-07`）、离线可跑（`ACC-H-08`）。
