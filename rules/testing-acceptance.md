# 测试与验收规则

> 依据：规格 §10.3、§12、§14，以及各章的 `ACC-*` 验收项。
> 核心原则：**没有证据的"完成"不算完成。**

## 1. 测试分层（缺一层即视为未完成）

| 层 | 范围 | 要求 |
|---|---|---|
| 单元 | 全部确定性逻辑（解析、校验、清洗、统计、信度、词频、数字一致性校验） | 关键算法 **100% 分支**；整体 `[SHOULD]` ≥ 85% |
| 契约 | Schema 校验、TXT↔JSON 往返、幂等性、值域拦截 | **必测**，含"一个正例 + 一个反例" |
| 集成 | `ST01 → ST03 → ST04 → ST06 → ST08/09 → ST11 → ST12 → ST10 → ST13 → ST14 → ST15`，**离线** | CI 必须跑通，输入用 `data/_example/` |
| 智能体 | 全部 cassette 回放 | **CI 零网络**；未录制即失败 |
| golden | 编码质量（准确率/宏 F1/多选 Jaccard）随提示词或规则变更的回归对比 | 变更元提示词、skills、编码规则时必须运行 |
| GUI | 关键路径 E2E（导入→校验→编码→复核→信度→报告） | 三平台冒烟（MS5 起） |
| 验收 | `ACC-*` 逐条对应测试用例 | 编号可追溯 |

## 2. ACC 编号追溯（硬性）

- 每个测试用例的函数名或 docstring 必须含对应 `ACC-*` 编号，例如 `def test_acc_m1_03_txt_json_roundtrip(): ...`
- `docs/dev/acceptance-traceability.md` 维护 `ACC-* → 测试文件::用例名` 映射；CI 检查是否存在"未覆盖的 ACC"。
- 验收项未通过时，不允许标记里程碑完成。

## 3. 必须存在的关键测试（最小集）

| 主题 | 关键断言 |
|---|---|
| 幂等 | 同输入 + 同配置两次运行 → 输出哈希一致（清洗、统计、信度、SVG） |
| 往返 | `parse_txt(render_txt(x)) == x`；`render(parse(txt))` 规范化后一致；`codebook` TXT↔JSON 往返 |
| 值域 | 非法 `value_id` **100%** 进 `_invalid.jsonl` 与复核队列，绝不静默丢弃 |
| 必答 | 必答题留空率 = 0 |
| 不可变 | L0 在同 run 内哈希不变；改动全部落 L1 + 审计 |
| 审计完整 | 100% 的编码值改动有对应审计记录（含 `reason` + `rule_ref`） |
| 红线静态检查 | 代码中不存在"随机改写 `values`"的写入路径（`ACC-M6D-05`） |
| 信度数值 | 规格附录 C 的 C-1…C-8 全部通过（含 `P_e=1` 返回 `null`、`α ≡ π` 等价性） |
| 数字一致性 | 报告数字一致率 100%；含"故意注入错误数字"的拦截用例 |
| 层级 | 三级结构 → 单层导出 → 再导入，层级完全还原（`ACC-CB-01`） |
| TXT 分类 | 8 类 TXT 均可被 `txt.detect_type` 正确分派；含 `DATA-108` 拒解析用例 |
| Harness | `ACC-H-01`…`ACC-H-11` 全覆盖 |
| 决策型 | `ACC-DC-01`…`ACC-DC-07` 全覆盖（含"无本地部署路径"断言） |

## 4. golden 集与效度

- 位置：`data/{version}/golden/`（示例数据放 `data/_example/golden/`），**冻结**并记版本与哈希。
- 规模：默认 100–200 条，覆盖全部选项；不足时按题目分层扩样。
- 指标：字段级准确率、宏平均 F1、混淆最多的选项对、非法值率（必须 0）、无法判定率。
- **信度 ≠ 效度**：报告必须同时给出信度与效度，或显式说明未做效度检验。
- 每次提示词 / skills / 编码规则变更，必须重跑 golden 并记录指标变化；**指标下降必须解释**。

## 5. 复现性测试

- 删 `results/`、`reports/`、`cache/` 后，用 `frozen/{run_id}` + manifest 重算，**统计/信度/图表**产物哈希一致。
- 无法逐字节一致的文件（含时间的图、LLM 输出）必须列入"**可复现性豁免项**"并写清原因。
- 每个 release 前执行一次"全新环境 + 断网"复现演练。

## 6. 证据格式（写进交付回复）

```
【证据】
- 命令：uv run pytest tests/test_codebook_parse.py -q
- 结果：12 passed（含 ACC-M1-03 / ACC-M1-04）
- 产物：data/_example/clean/codebook_validation.json（0 error, 3 warning）
- 哈希：sha256:...（两次运行一致）
```

## 7. 禁止事项（测试面）

1. 删除、跳过（`skip`/`xfail`）失败用例来"变绿"；确需跳过必须写明理由与恢复计划。
2. 放宽断言以适应错误实现。
3. 用 `sleep` 或重试掩盖幂等/并发缺陷。
4. 在 CI 中发起真实网络或真实付费调用（智能体一律 cassette）。
5. 声称"已验证"但说不出命令与输出。
