# 禁止事项（红线）

> 依据：规格 §5.4、§7.4、§11.4、§8.5，以及各章 `[MUST NOT]` 条目。
> **违反任何一条：立即停止当前工作，保留现场，报告给用户。** 不接受"下不为例"。

## A. 数据与学术红线（最严重）

| # | 禁止 | 为什么 |
|---|---|---|
| A1 | 对编码值做**随机或无记录**的改动 | 数据操纵，信度检验会自我实现 |
| A2 | 以"让指标达标"为目标调整参数、阈值、样本或选项 | HARKing / p-hacking，论文会被否 |
| A3 | 隐藏或延迟展示**不达标**的信度结果 | 学术诚信问题（校验器必须放行真值） |
| A4 | 无依据改写编码值（缺 `reason` 或 `rule_ref`） | L1 的唯一合法性来源是"有依据的复核" |
| A5 | 只裁决"妨碍达标的那部分分歧"，或按达标与否选择性裁决 | 必须对**全部分歧**执行同一套规则 |
| A6 | 把经调整/裁决的数据标注为"AI 原始编码" | 溯源欺骗 |
| A7 | 不披露裁决覆盖率与裁决依据分布 | 读者无法判断数据可信度 |
| A8 | 用"正态分布原则"描述名义型变量的分布 | 概念错误（名义变量无正态分布） |
| A9 | 用随机扰动副本充当信度检验的"编码员 B" | 循环论证；仅允许作带 `synthetic=true` 的测试 fixture |
| A10 | 删掉不一致样本或分歧选项来"提高"信度 | 选择性报告 |
| A11 | 修改信度系数实现或门槛以使结果达标 | 篡改度量 |

## B. 工程红线

| # | 禁止 | 替代做法 |
|---|---|---|
| B1 | 硬编码路径、模型名、端点、字段名、阈值 | 全部走配置（`config/default` + `config/{version}`） |
| B2 | 用内存对象/全局单例/环境变量传递业务数据 | 只走文件契约（环境变量仅密钥与工作区根） |
| B3 | 读取未在 `inputs` 声明的文件 | 显式声明依赖，执行器校验 |
| B4 | 把 `temp/`、`cache/` 的内容当作环节输入 | 这些目录可随时清理 |
| B5 | 跨 run 覆盖同名产物 | 新 run 新目录 + `CURRENT` 指针原子切换 |
| B6 | 静默降级（上下文超限、缺字体、缺 ffmpeg、解析失败、审核拒答） | 报错或记 flag + 日志 + 进复核队列 |
| B7 | 静默默认（缺配置时猜一个值） | fail-fast，指出缺哪一项 |
| B8 | 在静态区写入运行产物 | 运行区按 `{version}`/`run_id` 隔离 |
| B9 | 让 `STCX-analytics` 依赖 `STCX-agents` | 统计与信度必须纯计算 |
| B10 | 绕过统一返回信封自造返回结构 | 所有工具共用 `{status,data,warnings,errors,metrics,artifacts}` |

## C. 智能体红线

| # | 禁止 | 替代做法 |
|---|---|---|
| C1 | 让模型发明选项表外的编码值 | 值域校验 100% 拦截 + `_invalid.jsonl` |
| C2 | 一次调用塞入多个样本 | 单样本 × 全部题目；多样本批塞需显式开启并声明 |
| C3 | 默认把判定切碎成单字段（除非超预算降级） | 按规格 §17.2 的 9 步降级顺序，且记 flag |
| C4 | 把不同粒度（默认 / 分批）的结果静默混算 | 信度计算前检查 flag 一致性 |
| C5 | 未过准入门槛就把决策型来源计入信度 | 只能作 `prefilter`，并在报告中说明 |
| C6 | 未校准阈值就使用概率输出或做分流 | 逐题校准 + ECE 检查；ECE > 0.10 视为不可信 |
| C7 | 编造 `evidence`（片段不在原文中） | 子串校验，失败率必须为 0 |
| C8 | 跨环节用对话/内存续用会话状态 | 每环节独立调用，结果落盘 |
| C9 | 用重型框架的图/状态机串联环节 | 自研 `pipeline.yaml` + 文件契约 |
| C10 | 设计依赖本地大模型权重的默认路径 | 8 GB 显存跑不动 27B 级模型；决策型只走托管 API |

## D. 过程红线

| # | 禁止 | 替代做法 |
|---|---|---|
| D1 | 修改需求文档 | 停下来报告，由用户定稿升版 |
| D2 | 删除/跳过/放宽测试以变绿 | 修实现或报告 |
| D3 | 声称跑过未跑的命令、引用未实测的结论（如"某模型免费额度充足"） | 先实测，再写入文档与结论 |
| D4 | 跳过门禁（编码规则未 0 error 就交付；准入未过就接入来源） | 门禁即交付条件 |
| D5 | 擅自扩大任务范围（顺手重构、顺手新增功能） | 一次一个可验收增量；额外想法记入【下一步建议】 |
| D6 | 修改契约（Schema）不带迁移脚本与版本号 | 合同变更流程（`rules/collaboration.md`） |
| D7 | 在日志里写样本文本原文或密钥 | 默认脱敏；调试级需显式确认 |
| D8 | 引入 AGPL/传染性许可依赖进入内核链路 | 先查 `rules/security-cost.md` 的许可清单 |
| D9 | 未确认就把第三方 API 的能力/定价/合规写进文档或界面 | 标"待实测"，实测后回填 |

## 违规处理

1. 立即停止，**不要试图掩盖**（例如偷偷改回代码）。
2. 在回复中第一段说明：违反的是哪一条、影响范围、当前状态。
3. 给出修复方案与防止复发的检查项（优先做成自动化检查，而不是"下次注意"）。
