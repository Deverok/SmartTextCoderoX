## 1. 项目一句话

**SmartTextCoderoX**：一套单机、离线优先的**文本内容分析流水线应用**。用户只提供两样东西——**样本**（文本或多模态素材）与**编码规则文件**（类目表），系统产出**编码数据集 + 信效度证据 + 统计分析 + 图表 + 学术报告**。AI（DeepSeek / 智谱等）只是其中一个**可替换组件**，不是产品本身。

技术栈：Python ≥ 3.10（推荐 3.12）+ uv 多包工作区；GUI 用 Electron + Vue 3；数据格式 JSONL/JSON（机器权威）+ TXT（人工面）+ CSV/XLSX（交付面）。

## 4. 工作方式（硬性，逐条遵守）

1. **先计划后编码**：每个任务先输出计划，四要素齐全——`目标 / 输入输出（含契约） / 依赖与顺序 / 完成定义 DoD 与证据`。
2. **契约优先**：先写 JSON Schema 与失败用例，再写实现；不允许"先写代码再补格式"。
3. **小步交付**：一次只做一个可独立验收的增量；一个增量未过验收，不开始下一个。
4. **不许猜**：规格 §15.2/§15.4 里未决的问题，按其中的**建议默认**实现，同时留下 `TODO(DECISION)` 注释与配置位，并在回复里明确列出"我做了哪些默认假设"。
5. **不许静默**：任何降级、跳过、截断、重试、默认值，都必须**写日志 + 打 flag**（规格 §4.0.4、§17.2）。
6. **可复现优先**：每个步骤必须可单独运行、幂等、写 manifest（输入/输出哈希、配置哈希、代码版本、模型与参数）。
7. **不许改需求**：不得修改 `docs/需求规格说明书.md`。发现规格有误或缺失，**停下来报告**，提出修改建议，由我定稿后升版。
8. **不许改测试来通过**：测试失败就改实现或报告；删除/放宽断言必须先说明理由并得到确认。
9. **每条验收都要证据**：证据 = 测试用例名 + 运行命令 + 关键输出，或校验器报告。没有证据的"已完成"我不接受。
